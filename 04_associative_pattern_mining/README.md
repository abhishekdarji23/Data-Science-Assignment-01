# 🛒 Market Basket Pattern Mining

A small, real, end-to-end CRISP-DM data science project: mines "customers
who bought X also bought Y" association rules from grocery transaction
data (Apriori algorithm) and serves live recommendations for a shopping
cart in progress, through a FastAPI backend and a plain point-and-click
frontend.

Reproduced (scoped down, "not fancy," simple frontend + backend) from
Project 04 of
[`dlmastery/data_science_examples`](https://github.com/dlmastery/data_science_examples).
See [`PROMPTS.md`](PROMPTS.md) for exactly what was asked and how this
build's scope differs from the original.

## Quickstart

```bash
python3 -m venv .venv && source .venv/bin/activate     # optional but recommended
pip install -r requirements.txt

# 1. Generate data (synthetic — see data/generate_data.py to swap in real transaction data)
python data/generate_data.py

# 2. Mine association rules (Apriori)
cd src && python train.py && cd ..

# 3. Run the app
uvicorn app:app --reload --port 8004
```

Open **http://127.0.0.1:8004** — click items to build a cart and watch
recommendations update live (try clicking "diapers" 🙂).

Run the tests any time with:
```bash
python -m pytest tests/
```

## CRISP-DM summary

1. **Business understanding** — recommend items to add to a cart in
   progress, based on what tends to be bought together.
2. **Data understanding** — `data/generate_data.py`; long-format
   (transaction_id, item) transaction log with realistic, non-random
   co-purchase patterns baked in.
3. **Data preparation** — `src/data_prep.py`; pivots to a one-hot basket
   matrix.
4. **Modeling** — `src/train.py`; Apriori (mlxtend) → association rules,
   filtered and ranked by lift.
5. **Evaluation** — since this is unsupervised, "evaluation" means
   confirming mined rules are non-trivial (lift > 1) and match expected
   real-world patterns — verified in `AUDIT_REPORT.md` by checking that
   every pattern baked into the synthetic generator was actually
   rediscovered. Current run: **118 rules from 226 frequent itemsets**
   (see `models/metrics.json` for the live numbers after you train).
6. **Deployment** — FastAPI (`app.py`) + a small cart-builder dashboard
   (`static/`).

## Honest limitations of this build

- **Data is synthetic**, generated with explicit ground-truth association
  patterns (`BAKED_IN_RULES` in `data/generate_data.py`) because this
  build environment has no internet access to Kaggle. This is actually
  useful here: it lets the audit verify the mining pipeline by checking
  those patterns were rediscovered. Drop a real transaction log at
  `data/transactions_real.csv` (same two-column format) and re-run
  `train.py` — no code changes needed.
- **No video walkthrough is included.** Recording narration and uploading
  to YouTube isn't something this assistant can do. `WALKTHROUGH.md` is a
  written, code-ordered substitute, with a shot list at the bottom if you
  want to record one yourself in a few minutes.
- **This zip wasn't pushed to GitHub for you** — there's no GitHub write
  access available here. To publish it yourself:
  ```bash
  cd 04_associative_pattern_mining
  git init && git add . && git commit -m "Market basket pattern mining"
  git branch -M main
  git remote add origin https://github.com/<you>/<repo>.git
  git push -u origin main
  ```
- Deliberately **simple**, per your instruction: no React build, no
  FP-Growth comparison, no AutoML, no database — see
  `IMPLEMENTATION_PLANS.md` §9 for the full list of what was left out and why.
