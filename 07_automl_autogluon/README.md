# 🧠 AutoML Stacking — Customer Churn

A small, real, end-to-end CRISP-DM data science project: trains a zoo of
5 different classifiers, stacks their out-of-fold predictions into a
meta-learner (the core technique AutoGluon itself is built on), and
serves a leaderboard plus live churn scoring through a FastAPI backend
and a plain dashboard.

Reproduced (scoped down, "not fancy," simple frontend + backend) from
Project 07 of
[`dlmastery/data_science_examples`](https://github.com/dlmastery/data_science_examples).
See [`PROMPTS.md`](PROMPTS.md) for exactly what was asked, and — important
for this one — why the real **AutoGluon package was deliberately not
used** (it pulls in PyTorch/LightGBM/CatBoost/Ray, directly conflicting
with "keep it simple"). This build reimplements AutoGluon's core
stacking technique directly with plain scikit-learn instead.

## Quickstart

```bash
python3 -m venv .venv && source .venv/bin/activate     # optional but recommended
pip install -r requirements.txt

# 1. Generate data (synthetic — see data/generate_data.py to swap in real Kaggle data)
python data/generate_data.py

# 2. Train the model zoo + stacked ensemble
cd src && python train.py && cd ..

# 3. Run the app
uvicorn app:app --reload --port 8007
```

Open **http://127.0.0.1:8007** — see the leaderboard (5 base models +
the stacked ensemble), and score a customer yourself to see every base
model's individual opinion alongside the final stacked prediction.

Run the tests any time with:
```bash
python -m pytest tests/
```

## CRISP-DM summary

1. **Business understanding** — predict which customers are at risk of
   churning, using an ensemble of models rather than betting on one
   algorithm choice.
2. **Data understanding** — `data/generate_data.py`; telco-churn-style
   data with genuine churn drivers baked in (contract type is by far the
   strongest).
3. **Data preparation** — `src/data_prep.py`; fixed-category one-hot
   encoding so single-row live scoring never silently mismatches
   training-time columns.
4. **Modeling** — `src/train.py`; 5-model zoo, 5-fold out-of-fold
   stacking, logistic regression meta-learner.
5. **Evaluation** — leaderboard ranked by ROC-AUC. Current run: **stacked
   ensemble ≈0.7385, narrowly ahead of the best single model (logistic
   regression, ≈0.7382)** — a small, honest lift (see `models/metrics.json`
   for the live numbers, and `AUDIT_REPORT.md` for why this modest gain
   is expected, not a bug).
6. **Deployment** — FastAPI (`app.py`) + a small leaderboard + scoring
   dashboard (`static/`).

## Honest limitations of this build

- **No actual AutoGluon dependency.** The real package's dependency
  weight (PyTorch/LightGBM/CatBoost/Ray) conflicts with "keep it
  simple" — this build reimplements the underlying stacking technique
  directly. See `PROMPTS.md` for the full reasoning.
- **Data is synthetic**, with genuine (non-random) churn drivers baked
  in, because this build environment has no internet access to Kaggle.
  Drop a real `data/churn_real.csv` in (schema in `src/data_prep.py`)
  and re-run `train.py` — no code changes needed.
- **The stacking lift is small, and that's shown, not hidden** — see
  "An honest result" in `PROMPTS.md` and `AUDIT_REPORT.md` §2 for the
  full picture, including why the meta-learner's per-model weights make
  sense given each base model's own accuracy.
- **No video walkthrough is included.** Recording narration and uploading
  to YouTube isn't something this assistant can do. `WALKTHROUGH.md` is a
  written, code-ordered substitute, with a shot list at the bottom if you
  want to record one yourself in a few minutes.
- **This zip wasn't pushed to GitHub for you** — there's no GitHub write
  access available here. To publish it yourself:
  ```bash
  cd 07_automl_autogluon
  git init && git add . && git commit -m "AutoML stacking: customer churn"
  git branch -M main
  git remote add origin https://github.com/<you>/<repo>.git
  git push -u origin main
  ```
- Deliberately **simple**, per your instruction: no React build, no
  hyperparameter search, no database — see `IMPLEMENTATION_PLANS.md` §9
  for the full list of what was left out and why.
